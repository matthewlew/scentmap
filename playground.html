XS 2. .us-section-hdr NEW components.css:2164 · app.js:4001,4009,4026,4036
.us-section-hdr implements the same uppercase label pattern as .sec-label (caption size, 700 weight, wide letter-spacing, text-tertiary) but with a unique padding var(--sp-xs) var(--sp-lg) 2px and a top margin. It was created because the author needed a section header inside the search modal and didn't want to override .sec-label's margin. The right fix is to let the parent control spacing via gap, not a separate class.

CSS — Magic Numbers
Hard-coded pixel values that should reference design tokens.
XS 4. .cmp-edu-wrap border-radius: 16px 16px 0 0 NEW components.css:1899
The score education overlay uses border-radius: 16px 16px 0 0. This is the bottom-sheet rounding pattern — the same value used by .sheet. It should use var(--radius-xl) (which resolves to 16px via the token scale) so both stay in sync if the sheet radius ever changes.
Current
/* components.css:1899 */
.cmp-edu-wrap {
  border-radius: 16px 16px 0 0;
  /* ... */
}
Fix
/* components.css:1899 */
.cmp-edu-wrap {
  border-radius: var(--radius-xl)
                 var(--radius-xl) 0 0;
  /* ... */
}
XS 5. .brand-count-chip margin-left: 3px NEW components.css:1505
margin-left: 3px is off the 4px grid. The spacing scale's smallest values are --sp-micro (2px) for optical nudges and --sp-xs (4px) for layout. 3px is not defined. Use var(--sp-micro) if the intent is optical, or remove and let the parent flex gap handle it.
Current
.brand-count-chip {
  margin-left: 3px; /* off-grid */
  font-size: var(--fs-meta);
  font-weight: 500;
  color: var(--text-tertiary);
}
Fix — use token or remove
.brand-count-chip {
  /* Option A: optical nudge token */
  margin-left: var(--sp-micro);

  /* Option B: remove margin, use
     parent gap instead */
  font-size: var(--fs-meta);
  font-weight: 500;
  color: var(--text-tertiary);
}
XS 6. Hardcoded box-shadow in .frag-picker-wrap and .note-popup NEW components.css:2268, 2304
Both floating overlays use hand-crafted box-shadow values instead of the shadow scale. The design system defines --shadow-sm, --shadow-md, --shadow-lg. 0 8px 24px var(--fade-strong) and 0 8px 32px var(--fade-strong) are both "elevated floating panel" — use var(--shadow-lg).
Current
/* frag-picker-wrap */
box-shadow: 0 8px 24px
  var(--fade-strong);

/* note-popup */
box-shadow: 0 8px 32px
  var(--fade-strong);
Fix
/* Both */
box-shadow: var(--shadow-lg);

/* Verify --shadow-lg definition in
   design-system.css matches intent.
   If not, update the token, not
   the component. */
JS — Inline Appearance Styles
Inline style="" attributes in app.js that set visual appearance (color, font-size, font-weight). Per pre-PR checklist: inline styles should be structural only (layout, position). Appearance must use class names.
S 7. .dot style="background:..." vs style="--fam-bg:..." NEW app.js — ~15 render sites
The .dot component uses background: var(--fam-bg, var(--fam-default)). The canonical way to color it is style="--fam-bg: ${color}" (sets the CSS custom property). However, many render sites in app.js use style="background: ${color}" directly, bypassing the component contract. Both work today, but the CSS-var approach is the contract: if .dot gains a hover variant or dark-mode override that modifies --fam-bg, inline background will override it silently.
Current — mixed approaches
/* Correct (CSS var approach) */
`<div class="dot"
  style="--fam-bg:${famColor}">`

/* Wrong (bypasses component) */
`<span class="dot"
  style="background:${famColor}">`
`<span class="dot dot--md"
  style="background:${color}">`
--fam-bg var (correct)
Canonical — always use --fam-bg
/* All dot render sites: */
`<div class="dot"
  style="--fam-bg:${color}">`

`<span class="dot dot--md"
  style="--fam-bg:${color}">`

/* Search for: */
/* class="dot" style="background */
/* class="dot--md" style="background */
Identical visually, correct contract
Grep to find all sites
grep -n 'class="dot' js/app.js | grep 'background'
grep -n 'class="dot--md' js/app.js | grep 'background'
XS 8. Inline note location label styling NEW app.js:1011, 1041
Two render sites style a location sublabel with identical inline appearance rules: color:var(--accent-primary); font-weight:700; text-transform:uppercase;. This is visual styling that should be a class, not an inline style. The pattern is: a compact uppercase accent label — similar to .text-label but in accent color. Add a utility .text-label--accent or reuse .text-label with a semantic accent context.
Current — inline appearance
/* app.js:1011 and :1041 */
`<div class="list-item-sublabel text-meta"
  style="color:var(--accent-primary);
         font-weight:700;
         text-transform:uppercase;">
  ${t.location}
</div>`
Top Note
Migration — add .text-label--accent to design-system.css
/* design-system.css — add utility: */
.text-label--accent {
  color: var(--accent-primary);
}

/* app.js:1011 and :1041: */
`<div class="text-label text-label--accent">
  ${t.location}
</div>`

/* .text-label already handles: */
/* font-size: caption, 700 weight,
   uppercase, letter-spacing */

XS 9. style="font-size: 64px" on compare match score NEW app.js:4977
The compare panel renders the match percentage as a 64px hero number using an inline style="font-size: 64px". This is an appearance override outside the type scale. 64px is a valid display size but it's not defined as a token. Either add --fs-display: 4rem to the type scale and a .text-display utility, or accept it as a one-time inline (the score hero is truly unique and unlikely to appear elsewhere).
Current
/* app.js:4977 */
`<div class="text-heading"
  style="font-size: 64px;
    color: ${matchPct >= 60
      ? ca.accent
      : 'var(--text-primary)'}">
  ${matchPct}%
</div>`
84%
Option A — add .text-display token (preferred)
/* design-system.css — add: */
--fs-display: 4rem; /* 64px hero numbers */

/* design-system.css utilities: */
.text-display {
  font-family: var(--font-display);
  font-size: var(--fs-display);
  line-height: var(--lh-tight);
  letter-spacing: var(--ls-tight);
}

/* app.js: */
`<div class="text-display"
  style="color: ${accent}">
  ${matchPct}%
</div>`

/* color is dynamic (accent varies
   by frag) — structural inline ok */
84%
Recommendation
Add .text-display. The score hero is the highest-frequency visual element in the Compare panel — it deserves a named token. Also prevents future devs from inventing another "big number" with a different magic size.
XS 10. .sec-label with inline style="color:${accent}" NEW app.js:4551, 4555
The compare panel's "Swap" sections render section labels colored to match each fragrance's family accent. This is done with style="color:${ca.accent}" on .sec-label. The dynamic accent is unavoidable (it varies per-frag), so the inline style is acceptable — but it mixes an appearance property (color) inline. The correct approach is to set the dynamic value as a CSS custom property and reference it in a class modifier.
Current — inline color
/* app.js:4551 */
`<div class="sec-label"
  style="color:${ca.accent}">
  Swap ${shortA}
</div>`
Swap Santal 33
Better — CSS var + .sec-label--colored
/* design-system.css — add utility: */
.sec-label--colored {
  color: var(--sec-label-color,
             var(--text-tertiary));
}

/* app.js: */
`<div class="sec-label sec-label--colored"
  style="--sec-label-color:${ca.accent}">
  Swap ${shortA}
</div>`
Swap Santal Blush
Note
This is a low-priority refinement. The current approach works and is readable. Migrate if the pattern appears in 3+ more places, or when doing the broader anti-pattern cleanup pass.
