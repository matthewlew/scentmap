## 2024-03-14 - Mobile Filter Toggle ARIA State Management
**Learning:** Even simple toggle buttons that show/hide panels using standard CSS classes (like `open`) need explicit ARIA state synchronization (`aria-expanded` and `aria-controls`) to communicate their function and state to screen readers.
**Action:** When implementing show/hide toggles via JavaScript `classList.toggle`, always capture the returned boolean state and immediately sync it to the triggering button's `aria-expanded` attribute. **Learning:** When text inputs rely on a `placeholder` for visual context (e.g., in a universal search bar) and that placeholder is dynamically updated via JavaScript based on state, the `aria-label` must also be explicitly synchronized in code. Relying solely on `placeholder` is an accessibility anti-pattern, but adding a static `aria-label` in HTML is insufficient if the context changes later.
**Action:** Whenever dynamically modifying an `input.placeholder` property in JavaScript, always add a corresponding `input.setAttribute('aria-label', ...)` to keep screen readers synchronized with the current visual intent.
