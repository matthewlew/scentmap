## 2024-03-14 - Mobile Filter Toggle ARIA State Management
**Learning:** Even simple toggle buttons that show/hide panels using standard CSS classes (like `open`) need explicit ARIA state synchronization (`aria-expanded` and `aria-controls`) to communicate their function and state to screen readers.
**Action:** When implementing show/hide toggles via JavaScript `classList.toggle`, always capture the returned boolean state and immediately sync it to the triggering button's `aria-expanded` attribute. Also, remember that `aria-controls` should be hardcoded in HTML to establish the relationship.
## 2023-10-25 - Placeholder Accessibility for Screen Readers
**Learning:** In Scentmap's app, multiple input components (e.g., search inputs and dynamic comboboxes) relied solely on visual `placeholder` attributes to communicate their purpose to users. However, `placeholder` text is not reliably read by screen readers across all contexts, leading to unlabelled form fields for assistive technologies. Additionally, dynamic updates to input contexts via JavaScript were altering placeholders without corresponding updates to accessible names.
**Action:** Always ensure search/text inputs include an explicit `aria-label` attribute corresponding to their placeholder. When JavaScript dynamically mutates an input's `placeholder` (such as switching an input from a general search to a comparison search), use `input.setAttribute('aria-label', ...)` to synchronously update the accessible name for screen readers.
