## 2024-03-14 - Mobile Filter Toggle ARIA State Management
**Learning:** Even simple toggle buttons that show/hide panels using standard CSS classes (like `open`) need explicit ARIA state synchronization (`aria-expanded` and `aria-controls`) to communicate their function and state to screen readers.
**Action:** When implementing show/hide toggles via JavaScript `classList.toggle`, always capture the returned boolean state and immediately sync it to the triggering button's `aria-expanded` attribute. Also, remember that `aria-controls` should be hardcoded in HTML to establish the relationship.
## 2026-06-15 - Search Input Accessibility Validation
**Learning:** Relying solely on `placeholder` attributes for context inside text input fields (`<input type="text">`) is a major accessibility anti-pattern because screen readers often skip them or misinterpret their intent, leaving visually impaired users without clear instructions on what to search for.
**Action:** Always provide an explicit, descriptive `aria-label` attribute on search input fields (e.g. `aria-label="Search fragrances..."`) that closely mirrors the visual placeholder. Additionally, when using JavaScript to dynamically change placeholders across different search contexts (e.g. switching between universal search and comparison search), always explicitly sync `setAttribute('aria-label', ...)` alongside the `placeholder` updates.
